# C1: fixed completion-count comparator on existing evidence

Defined before executing the comparator calculation, 2026-09-29. This packet
does not reopen a scientific campaign. It walks the already recorded complete
four-action, five-decision tree; no environment transition, neural training,
new random stream or patient-model query is permitted. All old outputs remain
unchanged. The rule and its analysis code are committed before the saved replay.

## Fixed rule and information boundary

For each site count jobs whose observed stage is `support`. Choose `idle` when
both counts are zero, `balanced` on a positive tie, otherwise `left` or `right`
for the larger count. This corresponds to committing the existing grid action,
not changing the environment's FIFO dispatch. There are no fitted parameters,
response estimator, terminal lookahead or world-dependent branches.

The controller receives only `CompletionCounts(epoch, support_by_site)`.
It does not receive remaining work, exact delivered service, censoring flags,
cost-to-go, hidden world identity/change time, downstream countdowns or even
pending hours. Counts are derived from public task stages/site mapping. This is
a strict subset of the earlier synthetic `completion_events` view. It is not
asserted to match an actual site's logging capability; E1 leaves that open.

Pending commitments can cause over-allocation; job counts ignore partially
finished tasks and task-size differences. Those are disclosed limitations of
the fixed rule, not invitations to tune after seeing results. The unchanged
common terminal closure and its full charges remain part of every path cost.

## Comparison and validation

Report all eight cells and both individual persistent-change worlds. Weight by
the unchanged finite-world probabilities. Compare with the existing
information-free fixed-balanced method and the known-law completion-information
diagnostic bound. Do not claim a fair comparison to full-progress identification
MPC or select a best rule per cell. This is descriptive deterministic arithmetic,
not a new Monte Carlo estimate or confidence interval.

Tests cover input rejection, site symmetry, stage counting, hidden-field
poisoning, cost-insensitive actions, continuity, duplicate/missing-edge errors,
closure inclusion and no simulator/planner invocation. Upstream independent
row/hash audit runs before and after the saved replay. The result must not
undercut the richer-information diagnostic bound. Record source hashes and
local execution commit; refuse output replacement. A repeated computation must
reproduce the summary exactly.

## What completes C1

A tested deployable count-only function plus traceable recorded-path comparison
closes this bounded software packet. It does not complete a censored-data
identification-MPC or history-conditioned frozen policy comparison. If the rule
is suboptimal, its gap is only headroom beyond this rule, not an RL advantage.
Do not add noise, alter actions, fit a rule on these evaluation trees or start
DDPG training in response. Realistic observation/response calibration and a
separately approved prospective protocol remain prerequisites for further work.
